## 摘要
大语言模型越来越需要生成符合预定义模式的结构化输出，其中一种常见约束是从有限的有效字符串集合中进行选择。当前的约束解码系统通过通用语法编译来处理这一问题，但当有效值数量增至数千时，编译会变得异常缓慢，形成基数壁垒。我们提出了 Trie 自动机，一种利用有限集合结构（共享前缀、有限深度、已知基数）并通过 Aho-Corasick 多模式匹配预计算每个节点 token 掩码的专用机制。与 vLLM 和 SGLang 的主要后端之一 XGrammar 相比，该 Trie 的每步有效 token 计算快 7 倍（0.65 微秒 vs. 5.8 微秒），在 K >= 300 时编译快 2--6.5 倍。由于预计算掩码使无状态服务路径能够绕过引导式解码流水线，这一优势在批量服务中进一步放大：批量大小为 256 时，端到端 vLLM 吞吐量达到 219 req/s，而 XGrammar 为 7.5 req/s（29 倍）。这 29 倍提升既包括算法加速，也包括只有预计算掩码才能带来的集成路径节省。在七个 tokenizer 家族（词表规模 32K--262K）上，Trie 在 K 高达 10,000 时仍保持低于 100 毫秒的编译时间，并保持每步成本不随集合大小变化，同时保证 100% 的输出有效性。

## Abstract
Large language models increasingly need to generate structured outputs that conform to predefined schemas, with one common constraint being selection from a finite set of valid strings. Current constrained decoding systems handle this through general-purpose grammar compilation, which becomes prohibitively slow as the number of valid values grows into the thousands, a cardinality wall. We introduce the trie automaton, a specialized mechanism that exploits finite-set structure (shared prefixes, bounded depth, known cardinality) via Aho-Corasick multi-pattern matching to precompute per-node token masks. The trie achieves 7X faster per-step valid-token computation (0.65 us vs. 5.8 us) compared to XGrammar, one of the primary backends in vLLM and SGLang, and 2--6.5X faster compilation at K >= 300. Because precomputed masks enable a stateless serving path that bypasses the guided decoding pipeline, this advantage compounds in batch serving: end-to-end vLLM throughput reaches 219 req/s vs. XGrammar's 7.5 req/s at batch size 256 (29X). The 29X combines the algorithmic speedup with integration-path savings that only precomputed masks can unlock. Across seven tokenizer families (32K--262K vocabulary), the trie maintains sub-100ms compilation up to K = 10,000 and flat per-step cost regardless of set size, while guaranteeing 100% output validity.

## 1. 论文的核心问题与整体含义

- **研究背景**：大语言模型（LLM）在结构化输出（如工具调用、分类、实体链接）中，常需要从有限字符串集合 $\{e_1,\dots,e_K\}$ 中选择一个合法值。现有约束解码系统（如 XGrammar、Outlines、SGLang）将此类约束统一编译为通用有限状态机（FSM）或语法解析器，未区分约束复杂度。
- **核心问题**：当 $K$ 增大到数千（例如 1,000–10,000）时，通用编译流水线出现“基数墙”：编译时间随 $K$ 和字母表大小快速增长，每步掩码计算开销为 $O(V\cdot\ell)$，导致编译和推理都不可用。主流提供商纷纷设定枚举上限（OpenAI 1,000、Gemini ~120、Anthropic ~200），限制了规模化应用。
- **整体含义**：不同约束类型应使用不同执行机制。有限集具有共享前缀、有限深度、已知基数等可利用结构，因此可以设计专用后端以突破基数墙，同时保持输出 100% 有效。

## 2. 方法论

- **核心思想**：构建字符级 Trie（前缀树）编码所有枚举值，利用 Aho-Corasick（AC）多模式匹配将 BPE token 与 Trie 路径对齐，预计算每个 Trie 节点的合法 token 集合 $valid[n]$；解码时只需 $O(1)$ 查询预计算掩码，无需每步扫描整个词表。
- **BPE-Trie 对齐问题的解决**：
  - 一个 BPE token 可能跨越多个 Trie 边（如 token `medical` 覆盖 7 个字符节点），需判断 token 从节点 $n$ 出发是否能沿着 Trie 路径走到叶子或内部节点。
  - 将词表中所有 token 的字符串作为模式集，构建 AC 自动机（复杂度 $O(V\cdot\ell)$）；再对 Trie 做深度优先遍历，同时维护 AC 状态，在每步报告匹配模式并记录到对应起点节点。
  - 总预计算复杂度从朴素 $O(N_{chars}\cdot V\cdot\ell)$ 降至 $O((N_{chars}+V)\cdot\ell)$，其中 $N_{chars}=\sum_i |e_i|$ 是枚举值总字符数，$V$ 是词表大小，$\ell$ 是最大 token 字符长度。
- **解码流程**：在每个生成步，根据当前 Trie 节点直接取得 $A(s_t)=valid[s_t]$，应用 bitmask 到 logits。每步掩码计算成本为 $O(|valid[s_t]|)$，经验上在 3–4 个字符前缀后有效 token 数降至 10–100，因此几乎恒定（0.65 μs）。
- **关键命题**：Trie 自动机与 FSM 在可解码词表 $V_{dec}$ 上产生完全相同的约束分布 $p_c^{FSM}(y_t|y_{<t})=p_c^{trie}(y_t|y_{<t})$，因而贪心解码和固定种子采样的输出一致（Proposition 1）。依据是 Trie 与最小 DFA 同构（Myhill-Nerode 等价类）。
- **复杂度对比**（论文 Table 1 简化）：
  - 编译：FSM $O(N_{chars}\cdot|\Sigma|\cdot\log N_{chars})$，Trie $O((N_{chars}+V)\cdot\ell)$；在 $K=2000$ 时从约 1540 万运算降至约 37 万运算，约 40 倍加速。
  - 每步掩码：FSM $O(V\cdot\ell)$（约 128K 次查找），Trie $O(|valid[s_t]|)$（约 50–500 次），约 100 倍加速。
- **扩展机制**：支持混合 schema 路由（枚举部分交给 Trie，结构化部分交给 FSM/PDA）；对 $K>50,000$ 提出分层 schema 重写（将基数降至 $O(\sqrt{K})$）和投机短路（top-k 召回）作为未来方向。

## 6. 主要结论与发现

- **突破基数墙**：Trie 自动机将有限集约束解码的实用上限从约 1,000 扩展到约 100,000，编译时间在 $K$ 从 10 到 100,000 保持近似平坦（30–67 ms）。
- **性能优势**：
  - 每步有效 token 计算：0.65 μs，相比 XGrammar 的 5.8–9.5 μs 快约 7–9 倍；相比 LLGuidance 的 73–141 μs 快 110–215 倍。
  - 编译：在 $K\ge 300$ 时快 2–6.5 倍；在小词表上更明显，大词表（Gemma3-262K）时在 $K=1,000$ 仍快 1.2 倍。
  - 端到端 vLLM 吞吐：批量 256 时 219 req/s vs XGrammar 7.5 req/s（29 倍），且超过无约束吞吐（104 req/s），因为 trie 提前终止。
- **输出等价性与有效性**：Trie 与 FSM 在可解码词表上产生完全相同的输出（Proposition 1 验证），在所有 $K$ 和数据集上保证 100% 有效性；无约束解码在部分数据集上有效性低至 6.6%。
- **准确率影响**：在 24 个模型-数据集设置中，Trie 约束在 21 个上取得最高准确率，尤其对于小模型（Qwen3-1.7B Banking77 从 4.8% 提升至 24.8%）；强模型（Gemma3）在部分数据集上无约束准确率略高（差距 1–5 个百分点），但有效性仍低于 100%。
- **token 级 vs 字符级 Trie**：字符级 Trie 与 GENRE 风格 token 级 Trie 在 $K\approx 1,000$ 处出现编译时间交叉，之后字符级更优（$K=10,000$ 时快 7 倍），且与 tokenizer 无关。
- **匹配约束结构原则**：泛化到日期/时间等固定格式约束，字符位置掩码编译比 XGrammar regex 快 2–7,939 倍，说明专用后端适用于其他可正则化约束。

## 7. 优点

- **算法创新**：首次用 Aho-Corasick 多模式匹配解决 BPE token 与字符级 Trie 的对齐问题，将预计算从 $O(N_{chars}\cdot V\cdot\ell)$ 降至 $O((N_{chars}+V)\cdot\ell)$，实现亚 100ms 编译。
- **实用性强**：预计算掩码使解码路径无状态化，可绕过 vLLM 引导式解码流水线，在批量服务中额外获得集成路径收益；内存占用极小（$K=100,000$ 仅 8 MB，AC 自动机约 150 MB 可跨 schema 复用）。
- **理论保证与可验证性**：给出输出等价性命题及证明；与 GENRE 风格 token Trie、受控预计算对比、不同抽象层次的掩码成本测量，确保结论的算法性而非实现语言差异。
- **全面实验**：覆盖 7 个 tokenizer 家族、多个模型、4 个分类数据集、真实高基数 ICD-10-CM、批量服务吞吐、消融、内存分析，证据充分。
- **工程可落地**：实现为 Rust + PyO3，可作为 LogitsProcessor 集成 vLLM；代码将发布。

## 8. 不足与局限

- **约束范围狭窄**：仅优化平面有限集选择，生产 schema 常包含嵌套对象或数组，仍需通用 FSM/PDA 后端处理结构部分；混合 schema 的端到端服务吞吐未验证。
- **集成路径依赖引擎**：29 倍端到端吞吐是 vLLM 特定结果，因为 vLLM 的 guided decoding 管线开销较大；在 SGLang 或 TensorRT-LLM 上，集成收益可能不同。文章明确指出该数字不应视为引擎无关。
- **动态更新非增量**：枚举集合变化需要完全重新编译（约 37 ms，虽可接受但不是增量更新）。
- **小 $K$ 场景优势有限**：当 $K<50$ 或一次性查询且 $K<500$ 时，LLGuidance 的接近零编译可能优于 Trie；XGrammar 在极小 $K$ 时总编译时间更短。
- **准确率受模型能力限制**：在高基数（如 $K=74,719$ ICD-10-CM）下，Trie 保证形式有效，但模型分类准确率接近 0%，说明约束解码不能弥补模型能力不足。
- **投机与分层扩展未充分验证**：分层重写和投机短路仅为初步方向，实验显示在 $K=5,000$ 时分层反而更慢，需进一步研究。
- **GPU 掩码趋势**：如果未来推理引擎全面将掩码移至 GPU，CPU 每步优势会减弱，不过编译时间优势依然存在。
